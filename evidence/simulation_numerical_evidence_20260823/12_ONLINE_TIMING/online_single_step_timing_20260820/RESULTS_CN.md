# 在线单步耗时结论

原来的 `777.3 s` 是完整轨迹的 PyMC 推断中位时间，不是单步在线决策时间。本轮补测采用“收到一次新的 pH 观测，到输出下一次加液动作”的定义。

| 方法 | 单步计时结果 | 说明 |
|---|---:|---|
| PyMC variable-K | 中位 61.10 s，范围 37.98-84.92 s | 三次新进程重复；第 1 次观测；每个 K 使用 300 draws、1 chain；包含 K=1/2/3 拟合、证据比较、后验提取和剂量求解 |
| PyMC 8 步代表轨迹 | 中位下界 272.76 s，范围 29.15-366.73 s | 逐步 SMC 计时加剂量求解；不含模型构建和文件 I/O，因此是下界 |
| PF，1,000 粒子 | 中位 27.995 ms，P95 48.219 ms | 15 个案例；包含后验更新和动作选择 |
| 最新 PF 蒸馏模仿学习 | 0.1299 +/- 0.0566 ms；中位 0.1072 ms；P95 0.2217 ms | 30,000 次 CPU 热运行 |
| 最新 PPO | 0.1279 +/- 0.0540 ms；中位 0.1078 ms；P95 0.2136 ms | 30,000 次 CPU 热运行 |

模仿学习和 PPO 的单步耗时基本相同，因为二者使用完全相同的 `5-256-256-1000` actor 架构，只是权重不同。神经网络计时包括观测记录更新、状态构造与归一化、前向传播、argmax、加酸/加碱方向判断和体积解码；checkpoint 的一次性加载时间不计入热运行单步耗时。

需要注意，PyMC 环境没有可用的 C++ 编译器，PyTensor 使用 Python fallback，因此这些绝对耗时仅代表本机软件环境，不能作为硬件无关的保证。它仍足以说明：在当前实现下，PF、模仿学习和 PPO 都远低于约 20 s 的混合与传感时间，而逐步 PyMC 重拟合不适合作为在线控制器。
